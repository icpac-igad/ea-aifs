# AIFS ENS input-state build — 2026-06-04 00z

## Command

```bash
uv run s3_grib_pkl_input_aifsens.py \
    --date 20260604_0000 \
    --members 1-50 \
    --out s3_input_states \
    --gcs
```

> Environment: none to set up by hand. `s3_grib_pkl_input_aifsens.py` is a
> self-contained [PEP 723](https://peps.python.org/pep-0723/) script — its
> shebang is `#!/usr/bin/env -S uv run --script` and an inline `# /// script`
> block declares `requires-python >= 3.11` plus the deps (`numpy`, `obstore`,
> `fsspec`, `s3fs`, `gribberish`, `earthkit-regrid`, `google-cloud-storage`).
> `uv run` resolves and installs them into an ephemeral env on first run
> (~46 packages incl. transitive `scipy`), then executes. You can also run it
> directly as `./s3_grib_pkl_input_aifsens.py --date ...`.

This produces 50 pickles, one per member, each containing the merged
`(t-6h, t)` input state for AIFS ENS, and uploads them to
`gs://aifs-aiquest-us-20251127/20260604_0000/input/input_state_member_NNN.pkl`.
Local files are removed after a successful upload, so peak local disk stays
bounded to one ~800 MB pkl at a time (50 × ~800 MB ≈ 40 GB would not fit on
the 38 GB `/scratch` volume otherwise).

## What the script does

`s3_grib_pkl_input_aifsens.py` builds the 92-field input state that AIFS ENS
expects, sourced entirely from the ECMWF dissemination GRIB on
`s3://ecmwf-forecasts/` — without kerchunk.

### Why no kerchunk

Every `.grib2` on `s3://ecmwf-forecasts/` ships a small (~2 MB) JSON-lines
`.index` sidecar. Each line is one GRIB message with `_offset` / `_length`,
so the pipeline never reads the 6.3 GB body: it parses the index, filters
to the ~89 messages a member needs, byte-range fetches only those, and
decodes each one with `gribberish` (handles ECMWF's `grid_ccsds` packing,
verified pixel-identical to eccodes).

### Inputs per analysis cycle

For a single analysis time `t` the script automatically pulls **two** enfo
files and merges them into one input state of shape `(2, 542080)`:

| Timestep | File                                                                         |
| -------- | ---------------------------------------------------------------------------- |
| `t-6h`   | `<prev_date>/<prev_hh>z/ifs/0p25/enfo/<stamp>-0h-enfo-ef.grib2`              |
| `t`      | `<date>/<hh>z/ifs/0p25/enfo/<stamp>-0h-enfo-ef.grib2`                        |

For `--date 20260604_0000` that resolves to:

- `t-6h`: `20260603/18z/ifs/0p25/enfo/20260603180000-0h-enfo-ef.grib2`
- `t`:    `20260604/00z/ifs/0p25/enfo/20260604000000-0h-enfo-ef.grib2`

The 3 pure constants (`z`, `slor`, `sdor`) plus `lsm` are **not** in enfo;
they come from the deterministic `oper` 0h file at the analysis time only
(time-invariant — fetched once and replicated to both timesteps).

### Field groups (per member)

| Group        | Params                            | Levels                                  | Notes |
| ------------ | --------------------------------- | --------------------------------------- | ----- |
| surface      | 10u, 10v, 2d, 2t, msl, skt, sp, tcw | —                                     | enfo  |
| constants    | lsm, z, slor, sdor                | —                                       | oper 0h, sfc only |
| soil         | sot → stl1, stl2                  | 1, 2                                    | enfo, levtype `sol` |
| pressure (gh)| gh → z (× 9.80665)                | 1000, 925, 850, 700, 600, 500, 400, 300, 250, 200, 150, 100, 50 | enfo |
| pressure     | t, u, v, w, q                     | same 13 levels                          | enfo  |

Total: 8 + 4 + 2 + 13 + 13×5 = **92 fields**, each `(2, 542080)` float64
on the AIFS N320 reduced Gaussian grid.

### Pipeline per field

1. Filter the `.index` records to a single GRIB message.
2. Byte-range fetch the message from S3 (anonymous, `eu-central-1`).
3. Decode with `gribberish` → `(721, 1440)` float64 on a 0.25° grid that
   starts at lon=180; roll by `-Ni//2` so it starts at lon=0.
4. `earthkit.regrid.interpolate(..., {"grid": "N320"})` → `(542080,)`.
5. Stack `t-6h` and `t` along axis 0 → `(2, 542080)`.

### OOM-safety

Each param group is fetched / decoded / regridded, written to a partial
pickle, then freed; a final pass merges the partials into the single
`input_state_member_NNN.pkl`. Peak memory stays at one group instead of
all 92 fields, and a failed member is restartable from whatever partials
already exist on disk.

### Parallelism

Within a group, up to `MAX_WORKERS = 16` threads handle independent
byte-range fetches in parallel. Members themselves are processed
sequentially to keep memory bounded.

### Verification

Each pkl is checked for:

- 92/92 expected fields present, no extras
- all fields shape `(2, 542080)`
- all fields dtype `float64`

A `FAIL` line is printed if any check is off; otherwise `OK`.

### GCS upload

With `--gcs`, each verified pickle is uploaded to
`gs://aifs-aiquest-us-20251127/<datestr>/input/input_state_member_NNN.pkl`,
then the local copy is removed. The service-account key is resolved relative
to the script's own location (`coiled-data.json` next to
`s3_grib_pkl_input_aifsens.py`) via `__file__`, so the upload works
regardless of the working directory the script is launched from.

### Issues hit and how they were handled

- **Member 36 — transient S3 `SlowDown`.** A byte-range fetch hit
  `botocore … (SlowDown) … Please reduce your request rate` mid-member.
  The per-member `try/except` isolated it (the run finished `ok=49 fail=1`),
  and member 36 was re-run on its own afterward.
- **earthkit-regrid `No matrix found` on the single-member retry.** Wiping
  and rebuilding the `~/.cache/earthkit-regrid` cache wasn't enough on its
  own: with a cold cache, the 16 worker threads race the first inventory
  download and leave an orphan inventory `.sha256` with an empty matrix
  index (same corruption mode as a disk-full event). The fix was to warm the
  cache **single-threaded** in the script's own env — `MAX_WORKERS` is now
  overridable via the `S3_PKL_MAX_WORKERS` env var, so the retry ran as
  `S3_PKL_MAX_WORKERS=1 uv run … --members 36 --gcs` (52.7s, no race),
  which both warmed the matrix and completed the member.

### Operational notes for next time

- If a member fails on a transient S3 `SlowDown`, just re-run that member;
  it's not a data problem.
- After clearing the earthkit-regrid cache, warm it single-threaded
  (`S3_PKL_MAX_WORKERS=1`) for the first member, or pre-warm with one
  `ekr.interpolate(..., {"grid": "N320"})` call, before letting the 16-thread
  run hit a cold cache.
- The GCS service-account key must sit next to the script as
  `coiled-data.json` (the path is now resolved via `__file__`).
